# 漫剧平台优化 · 最优实施方案

> 日期：2026-08-06
> 基于《漫剧平台对标分析与优化建议》的选型落地版：只保留最优路径，明确做什么、不做什么、怎么落地
> 现状代码依据：`models.go` / `project_service.go` / `shortdrama_plan.go` / `templates/*.json` / `ProjectDetail.vue`

---

## 1. 选型原则

1. **吃透现有资产**：优先复用已存在的模板（ref2v 已支持 0-9 参考图）、字段（`Character.Portrait`）、能力（远程 ffmpeg、Ark API、`{{param}}` 占位符机制），避免引入新系统。
2. **一条链路打通优于横向铺开**：竖屏 → 锁角色 → 配音 → 字幕 → 切集，串成完整交付闭环后再谈多引擎/出海。
3. **文本已知就用文本**：对白是 LLM 生成的，字幕直接由对白文本生成 SRT，不需要 Whisper ASR。

---

## 2. 方案总览（决策表）

| # | 事项 | 选型 | 理由 | 工作量 |
|---|---|---|---|---|
| 1 | 竖屏 9:16 | 预设 + 模板宽高占位符 | 改动最小、漫剧刚需 | 0.5 天 |
| 2 | 角色一致性 | 视频改用 **ref2v + 角色标准像参考图** | 模板已存在、MiniMax H3 原生多参考图、8×L40 算力充足；比 IP-Adapter/InstantID 改动小且无需换模型管线 | 2-3 天 |
| 3 | 配音 TTS | 火山 TTS（Ark，复用现有密钥/客户端模式） | 已有 volc_engine.go、零新增依赖 | 3-4 天 |
| 4 | 字幕 | **对白文本直接生成 SRT + 可选烧录** | 对白是文本，无需 ASR；比 Whisper 准且零成本 | 1-2 天 |

| 7 | 多引擎/出海/登录 | **暂缓** | 生态封闭前先做透 MiniMax 单引擎（见 §8 YAGNI） | — |

## 3. 落地设计（贴合现有代码）

### 3.1 竖屏 9:16 预设

- **模板层**：4 个 `templates/*.json` 的 `width/height` 已是占位符，无需改模板。
- **前端** `CreateTask.vue` 分辨率预设下拉新增：
  - 720P 竖屏 = 720×1280
  - 1080P 竖屏 = 1080×1920
- **后端**：`RenderWorkflow` 的时长→帧数对齐逻辑（17k+5 网格）与宽高无关，无需改动。
- 附加：漫剧场景视频默认时长 3~8s 已存在，竖屏下同样生效。

### 3.2 角色一致性：i2v → ref2v + 标准像参考图（核心改造）

**现状**：`generateClaimedSceneImage` 已按出场角色注入权威 trait/style 文本；`Character.Portrait` 已生成标准像；场景视频用 `minimax_h3_i2v`（首帧图 → 视频）。

**改造**（`project_service.go` 视频生成处）：

1. 场景视频模板从 `minimax_h3_i2v` 切换为 `minimax_h3_ref2v`。
2. 构造素材清单：
   - `ref_image_0` = 场景首帧 `Scene.ImageFile`（图生视频的底）
   - `ref_image_1..N` = 出场角色（`Scene.Characters` 解析后查 `Character.Portrait`）的标准像，按角色名一一挂载
3. prompt 自动追加引用指令（结合 `buildSceneImagePrompt` 的既有注入逻辑）：
   ```
   <Picture 1> 这是角色「林夏」的标准形象，<Picture 2> 这是角色「陆川」……
   ```
4. 无角色场景退化为单参考图（等价旧 i2v），模板的"未提供节点自动裁剪"机制已覆盖。
5. **可视化**：`ProjectDetail.vue` 场景卡片标注"已锁角色 ×N"，生成失败时错误信息提示参考图问题。

**预期收益**：跨场景人物长相/服装稳定（H3 原生参考能力 + 首帧双保险），对标可灵主体库/灵映定妆图路线，且不引入新模型。

### 3.3 配音 TTS

1. **数据模型** `models.go` 新增 `Dialogue`：`SceneID`、`Character`（说话人）、`Text`、`AudioFile`、`Voice`（音色）、`Order`（句序）、`Status`。
2. **剧本生成**：`scriptScene` 结构增加 `dialogues: [{character, text}]`，剧本 prompt 要求每场输出台词（与现有 `characters` 数组同风格，缺失允许）。
3. **音色分配**：按角色 `Role` 固定映射（女主/男主/反派/配角各一音色，可覆盖），存 `Setting`。
4. **合成**：`volc_engine.go` 新增 `TextToSpeech(text, voice) → audio`（Ark TTS，与现有 GenerateText/GenerateImage 同模式、同 imageSem 限流复用）；逐 Dialogue 合成 → 存 `input/<pid>/dub/`。
5. **混音**：场景视频生成后，用远程 ffmpeg（`remote.go` + `runMerge` 既有能力）把该场景 Dialogue 音频按句序 `adelay` 排布 + `amix` 混入场景视频音轨（参考 edge-tts 的 ffmpeg 模板），保留原始环境音。
6. **UI**：场景详情展示对白文本、音色预览、重新合成按钮；视频就绪即带对白音轨。

### 3.4 字幕（文本直出，不做 ASR）

1. 每集字幕 = 该集所有场景的 Dialogue 按顺序拼接，按场景时长均分时间轴 → 直接生成 `SRT`（编码 UTF-8，字幕提前量 0.15s 等行业惯例）。
2. 两条产出：
   - **导出 SRT**（交付/剪辑期用，必做）
   - **烧录硬字幕**（可选开关）：远程 ffmpeg drawtext / subtitles filter 烧进成片，竖屏 9:16 下字体缩放需测试。
3. 对白缺失（用户手写场景无台词）时字幕为空，不阻塞流水线。

### 3.5 成片按集切集

- `MergeTask` 已有 `EpisodeN`，合并已支持按集；补：
  - **整剧一键合并**：按 `episode_n` 分组依次自动合并所有集。
  - 导出清单页：项目详情新增"成片交付"区块，列出每集成片 + SRT + 分镜图 + 角色像，批量打包下载（对应 spec 阶段 3 交付中心的最简版）。
- 转场/片头尾模板列为 P2，首版不阻塞。

### 3.6 Skill 接入（prompt 层增强）

1. 复刻 `worldwonderer/drama-skills` 的 3 个 references（`assets` 连续性决策 / `storyboard` 审查 / `video-prompts` 单镜动作+起止状态）到 `shortdrama/references/`。
2. `shortdrama_plan.go` 的 `scriptSystemPrompt` 按阶段注入：分镜场景生成时附加镜头动作/起止状态要求（直接改善 `Scene.Content` 作为视频提示词的质量，这是当前流水线的隐性短板）。
3. OnlyShot 的"候选帧先行"方法论先只沉淀为 review 规则文档，不做工程改造（YAGNI，见 §8）。

## 4. 实施计划

```
阶段 A（约 1 周）            阶段 B（约 1-2 周）            阶段 C（约 1-2 周）
┌────────────────────┐   ┌─────────────────────────┐   ┌────────────────────────┐
│ 1. 竖屏预设         │   │ 3. Dialogue 模型+TTS 合成 │   │ 5. 按集切集+交付清单     │
│ 2. ref2v 角色参考图  │   │ 4. SRT 生成+可选烧录      │   │ 6. skill references 接入│
│    （最核心，先验证） │   │    （依赖 A 的 ref2v）    │   │ 7. 端到端验证+文档       │
└────────────────────┘   └─────────────────────────┘   └────────────────────────┘
```

**依赖关系**：B 的混音需要场景视频存在（A 产物）；C 的切集需要 B 的音频+字幕。

**验证方式**（沿用现有测试风格）：
- 单测：素材清单拼装（角色标准像解析）、SRT 时间轴生成、TTS 音色映射表
- 端到端：1 个 3 场景项目跑通「竖屏 → 锁角色 → 配音 → 字幕 → 切集成片」

## 5. 关键风险

| 风险 | 应对 |
|---|---|
| ref2v 耗时翻倍（~120s→场景数×2） | 8 卡并行调度已能消化；角色图≥3 张时参考数量上限 9 足够；先小样本对比 i2v vs ref2v 一致性收益，收益不明显可回退文本注入模式 |
| H3 参考图对竖屏尺寸敏感 | 标准像生成 prompt 已固定竖构图，生成时加尺寸参数与场景一致 |
| 火山 TTS 音色与角色年龄/性别匹配 | 音色表提供 4-6 档（青年男/女、中年男/女、反派低音），首版手工选，后续再自动分配 |
| ffmpeg 混音在竖屏素材上的兼容性 | 复用 runMerge 已验证的 libx264/AAC 链路，参数同源 |

---

## 6. 明确不做（YAGNI）

- 多引擎适配器（Seedance/Kling/Vidu）：单引擎闭环后再议
- IP-Adapter / InstantID / 角色 LoRA 训练：H3 原生参考图路线已覆盖，不引入新模型管线
- Whisper ASR：对白为文本，SRT 直出更优；ASR 仅在未来"非对白音频识别"场景需要
- 出海多语言（字幕翻译/多语配音）：ReelShort 模式为商业模式问题，技术栈可后置
- 登录/权限：内网环境，交付外网化时再补
- 转场/片头尾模板：首版 concat 已可交付
